01Install

Quick start

You need Python ≥ 3.12, Node, and yt-dlp on your PATH. Everything else is optional.

install & run
uv sync                                               # backend
cd frontend && npm install && npm run build && cd ..  # frontend
uv run python main.py                                 # → http://127.0.0.1:5000

That's the whole install. Open the page, pick a channel, add a few YouTube channels and subreddits in Settings, and the rooms fill in.

Optional extras

The heavier features are each opt-in:

extras
uv sync --extra brain     # The Archive: faster-whisper + numpy (local transcription)
uv sync --extra editor    # The Composing Room: flask-sock (PTY terminal + LSP bridge)
Also nice to haveUnlocks
A running Ollama serverThe Archive's answers and summaries, and the written (rather than “wire”) Edition
rg (ripgrep)Fast project grep in the editor — falls back to os.walk
notify-sendA desktop ping ~10 min before a subscribed stream goes live
A language server (rust-analyzer, pyright, …)Completion and diagnostics in the editor

Every one of these degrades quietly. Miss them all and the app still boots — the feature just reports itself unavailable.

02The set

Channels & rooms

The set has two channels, chosen at / — a TV-style chooser. Press 1 or 2.

ChannelWhat's on
1The HubToday's paper, your videos, the wire, the archive and the workshop — a set of numbered rooms beside a console.
2The AnimeAll of AniList — the season, the week's schedule, your list and its ledger, the community — as a section of its own.

From anywhere, Spacegh goes to the Hub and Spacega to the Anime.

The console

There's no masthead. A slim console runs down the left — the wordmark, the channel switch, a search-everything button, your rooms as numbered preset keys, and Saved / Settings / skin — so every room starts at the top of the screen. The room you're in opens its own index under it (the Screening Room lists its views, your channels with their new counts, and what's queued). It folds to an icon rail, becomes a top bar on a phone, and on very wide screens (≥ 1780 px) hangs in the page's empty left margin. This manual's contents panel is the same console.

The rooms

The numbers aren't hardcoded — they're each room's position in your own running order, so switching one off in Settings → Rooms renumbers the rest. The default set:

NoRoomRouteWhat it is

A room's view state — its tab, filters, search — lives in the URL's query string rather than in component state, so opening a detail page and pressing Back restores exactly what you were looking at.

03One global player

The player

Every video — from any room — plays in one global player, straight from YouTube's own streams: real 1080p, no account, no embed, no third party.

  • A theatre, not a pop-up. The room goes dark, the picture's colours glow softly around it, and it's sized to the largest 16:9 that fits. Underneath: the title, the channel's face and subscriber count, Subscribe, Save, and a link that starts at this very second.
  • A seek bar that knows the video — YouTube's most replayed as a ridge above it, cut at every chapter, with the chapter's name on hover and beside the clock.
  • Programme notes beside it. The description with every timestamp seeking, every link to another video opening in the player and every hashtag searching the room; chapters; comments with faces, creator / verified / member / pinned / hearted marks, replies in place, Top or Newest, loading as you scroll; and The Archive's transcript (it follows the playhead) and summary.
  • Keeps playing when you leave. Esc tucks it into a corner dock that stacks and reorders; an up-next queue rolls into the next video when one ends. One <video> element per open video only changes its styling between expanded and docked, so playback never restarts.

How the 1080p works without an account or ffmpeg is in How it works → Streams. The player's keys are in Keyboard. Try the player demo on the tour.

04Channel 2

The Anime

A whole section built on AniList — its own top bar, and a file-tree index down the left where every view (and every useful place inside one) is one click away.

AniList account required. AniList now refuses unauthenticated queries, so your list, progress sync and the social side all need a connected account — see Connecting accounts.
ViewWhat's there
BrowseTrending, popular, top-rated and more, plus a genre/tag finder with every AniList filter — infinite scroll.
Seasons · ScheduleAny season's line-up; the week ahead as an airing grid with countdowns.
My ListYour shelves with fast editing, bulk tools, custom lists, export (JSON, CSV, MyAnimeList XML) and the sequel radar — what comes next after everything you've finished. Synced to AniList as you tap.
LedgerYour statistics computed from the list itself: genres, formats, scores, time spent, hot takes.
CommunityReviews, people's recommendation pairings (vote on them), today's birthdays and the hall of fame.
ChannelTrailers related to what you've watched, played like a station.
SocialThe forum (threads beside the list), the activity stream, your inbox and people — profile pages, follow, message — with a live preview of every post as others will see it.
Title pagesThe full dossier: cast with every dub's voice actors, characters, staff, studios, rankings, trends, a franchise watch-order guide, reviews and discussion.

Watching

Episodes play in-app through two independent scrapers — anipy-api (allanime / animekai) first, and weeb-cli's aniworld provider as the fallback — because two unrelated sites rarely break on the same day. Both return the same {sources, subtitles, headers} shape, so nothing downstream special-cases either. On startup Tubcal upgrades anipy-api from PyPI (the scraper's fixes ship as releases); TUBCAL_AUTO_UPDATE=0 turns that off.

Finishing an episode advances your AniList progress on its own: once playback passes TUBCAL_ANIME_WATCHED_PERCENT (default 80 %) the episode is marked watched — advance-only, once per episode.

The Reckoner

A watch-time calculator docked in the page's margin. Hover any title and tap C: it tallies the next unwatched episode — capped at what has actually aired — and each further C extends the run. It sums AniList's per-episode durations (24 min, flagged “estimated”, when AniList has none) into a total and a live “start now, finish at…” clock, and remembers the plan. The C key stands down for modifiers, text fields, an expanded player or editor, and for one second after g so the gc room jump still wins.

The curtain call

When you finish a season, velvet drapes part on the title: score it in your own AniList scale, join the finale's episode discussion (or start it), write the review while it's fresh, and put the next sequels on Planning or Watching — or read 終, series finished. It appears once per title, only for a season that has finished airing, and waits while the player is expanded.

AniList on a budget

AniList currently allows 30 requests a minute. Every read is cached, relation walks (sequels, watch order) are cached per title, the fan-out walkers check the remaining budget and stop early, and list edits apply locally at once and sync on a short debounce — a flurry of taps is one mutation. On a 429 a cooldown starts during which calls fail fast, so the stale cache is served at once.

          08What leaves the machine
Privacy

          
Binds to 127.0.0.1 and nothing else. Self-hosted fonts, no trackers, no analytics.

        

        

          
    
            
  • One file holds everything. Subscriptions, settings, watch history, playback progress, saved items, OAuth tokens and every byte of Archive data live in one git-ignored SQLite file, data/tubcal.db (with .bak-* snapshots beside it).
    • 
            
  • Anonymous YouTube. Every YouTube read goes through an anonymous session whose policy neither stores nor sends cookies, so there's no stable id linking your searches, feeds and playback. The consent cookie is sent as an explicit header; the one deliberate exception is importing your own subscriptions, which carries your OAuth token. A test (tests/test_httpc_anon.py) sweeps youtube.py's syntax tree and fails if any call site is neither anonymous nor authenticated.
    • 
            
  • Local models. The Archive and The Edition talk to Ollama on 127.0.0.1:11434 over plain HTTP; transcripts and vectors never leave the box.
    • 
            
  • Who it talks to. The platforms themselves (YouTube, Reddit, Hacker News + Algolia, GitHub, AniList), public Invidious instances for trending, comments and fallback search, the anime scrapers while you watch, and PyPI for the anipy-api self-update.
    • 
          

        

      


      
      

        

          09Under the cabinet
How it works

          
One Flask backend, one React SPA, one SQLite file. The interesting parts are the decisions that keep a single-person app fast and unbreakable.

        


        
The request path

        

          
frontend/src/api/client.jsReactapi() / useApi() unwrap data, or throw on ok === false

          

          
server/api/*Flask blueprintsevery response is ok(data) or err(msg); /api/* is no-store

          

          
server/cache.pyTwo-layer cachememory over SQLite; stale rows kept for when upstream fails

          

          
server/sources/*Source adaptersone module per platform's quirks

          

          
server/httpc.pyShared sessionsper-host spacing, anonymous reads, a large pool for HLS fan-out

          

          
the internetThe platformsYouTube · Reddit · HN · GitHub · AniList

        


        
Boot sequence

        
What main.py does, in order. Step through it:

        

          
    
          
    
            
    
            
    
          
    
        
    

        
    Caching is the load-bearing wall
    
        
    Two layers — an in-memory dict over a cache table in SQLite — so caches survive restarts. Expired rows are kept on purpose: if an upstream fetch fails, the stale payload is served instead of an error. That single decision is why Reddit's rate limiting can't take the app down. Play with it — this is cache.cached() with a 10-minute TTL (the YouTube RSS one):
    
        
    
          
    
            
            
            
            
            
          
    
          
    
            
    clock0:00
    
            
    
            
    
            
    
          
    
          
      
        
      

        
      Rate limits, respected
      
        
      
          
      
            
      UpstreamHow Tubcal stays under it
      
            
              
      RedditOne request every 3 s per host (HOST_INTERVALS); listings cached 5 min; stale served on 429.
      
              
      Invidious1 s spacing per public instance, so a channel page's burst becomes a gentle stream.
      
              
      AniList30 req/min budget tracked from X-RateLimit-Remaining; fan-outs stop early; a 429 starts a fail-fast cooldown.
      
              
      GitHub60 req/hr/IP unauthenticated, so everything is cached hard; a classic PAT raises it to 5,000.
      
                  
          
      
        
      

        
      Streams: real 1080p without an account or ffmpeg
      
        
      YouTube's open player clients now expose exactly one muxed rendition — 360p. Everything above ships as adaptive DASH, video and audio apart. Tubcal keeps 360p as an instant floor and, for each higher rendition, parses the stream's sidx index into byte-range segments and synthesizes an HLS playlist around them; hls.js muxes the two in the browser, fetching straight from googlevideo through a segment proxy.
      
        
      
          
      360p
      one muxed stream (itag 18) — plays instantly
      
          
      480p–1080p
            
      
              
      DASH video-only (avc1) + original-language AAC
      
              
      fmp4.py reads each sidx → byte ranges
      
              
      feeds.py serves a master + #EXT-X-BYTERANGE playlists
      
              
      hls.js muxes in the browser, native seeking
      
            
      
          
      
          
      live
      no DASH — stays on YouTube's own muxed HLS
      
        
      
        
      Dubbed and DRC audio tracks are dropped; only the creator's original track is kept. A resolve that only yields the 360p floor is cached briefly, so it heals itself on the next open.
      

        
      The Edition never computes on the request path
      
        
      A background thread builds one JSON payload per day into the editions table; GET /api/edition/latest is a single row read. Clustering (brain/cluster.py) is pure functions — canonical-URL hard-links, then greedy centroid clustering over unit vectors at a strict cosine threshold (0.80) — and has the deepest test coverage in the repo. Model synthesis is capped at six calls per build, time-boxed, and gated by a citation validator with a template fallback, so unvalidated model output can't reach a page. The lede alone gets a transcript block: if its top video is already in The Archive, the copy desk reads what was actually said.
      
        
      
          
      nothing installedWire editionhard-link clusters, template prose, every story shows its numbers
      
          
      + numpy + embed modelSemantic clustersthe same story found across rooms
      
          
      + chat modelEditedgrounded synthesis with citations
      
        
      

        
      The Archive answers in two passes
      
        
      A retrieved chunk is a ~45-second keyhole, and the sentence that answers the question is often just past its edge. So summarize.ask() runs two local LLM calls:
      
        
        
          
      1. Retrieve. Embed the question; brute-force cosine over every chunk vector in SQLite; keep the top 12.
        2. 
          
      2. Zoom. The model sees the numbered excerpts and names (JSON only, temperature 0) the ≤ 3 worth a closer read (TUBCAL_BRAIN_ASK_EXPAND).
        3. 
          
      3. Re-read. Those come back with two chunks either side (~± 90 s), deduped so no passage is sent twice, each with its provenance — title, channel, timestamps, position in the video, watch date, rewatch count.
        4. 
          
      4. Answer. The model writes the answer with citations; the deep-read ones are ringed in the UI. Anything malformed from the zoom pass falls back to the top-scoring excerpts — validate model output, never trust it.
        5. 
        
      

        
      Untrusted HTML, the editor sandbox, lazy imports
      
        
      Untrusted HTML is never injected. Comments and descriptions from YouTube, HN and AniList are walked with an allow-list into React elements — which is also what lets a timestamp seek, or a link to another video open in the player.
      
        
      The editor is sandboxed. Every client-supplied path resolves against EDITOR_ROOT and is rejected if it escapes — traversal, absolute paths, symlinks out. Writes are atomic (temp file + os.replace) behind an mtime precondition, so a stale buffer gets a conflict instead of clobbering your file; :w! forces. Try the rule:
      
        
      
          
      
            
          
      
          
      
            
          
      
          
      
          
      
          
      A symlink inside the root that points outside it is caught the same way: resolve() follows it first. That part needs a real filesystem, so it isn't simulated here.
      
        
      
        
      Heavy dependencies are lazy. anipy, weeb-cli, numpy, faster-whisper, rapidfuzz and flask-sock are imported inside the function that needs them and guarded — which is what lets minimal runtimes, down to the Android/Chaquopy build, boot at all.
      
      
      

      
      
      
        
      
          10server/api/*
      API reference
      
          
      Every route the Flask app registers, read straight out of the blueprints. The API is for the app's own UI — it binds to 127.0.0.1 and has no auth of its own — but it's plain JSON, so it's easy to script against locally.
      
        
      
        
      
          
      
            
      success
      { "ok": true,  "data": { … } }
      
            
      failure
      { "ok": false, "error": "message" }
      
          
      
          
      Paths use Flask's converters — <int:id>, <path:item_id>. query lists the parameters a handler reads from request.args; body the JSON keys a write reads. The list is generated by docs/tools/extract_routes.py.
      
        
      
        
      
          
      
          
      
          
      
          
        
      
        
      
      
      

      
      
      
        
      
          11Where everything lives
      Project layout
      
          
      Open a folder, pick a file — the note on the right says what it's for, with a link to the source.
      
        
      
        
      
          
      
          
      
        
      
        
      
          
      Adding a room
      
          
      Three edits kept in sync: an entry in frontend/src/lib/rooms.js, a component in pages/, and a route in App.jsx — plus the id in config.ROOM_IDS so the backend agrees.
      
          
      Adding a source
      
          
      server/sources/hackernews.py is the reference pattern: normalize(item), get_feed(), search(), get_item(), each wrapped in cache.cached(). New external fetches go through httpc.py, with a TTL constant added to config.py.
      
        
      
      
      

      
      
      
        
      
          12Hacking on it
      Develop
      
          
      Two servers in dev; one port in production mode, where Flask serves frontend/dist.
      
        
      
        
      
          
      
            
      dev mode
      

      uv run python main.py        # API on :5000
cd frontend && npm run dev   # UI on :5173, /api proxied

uv run pytest                # backend tests
uv run pytest tests/test_api.py::test_name -q   # a single test
      
          
      
          
      In production mode a UI change needs npm run build and a hard refresh, and a backend change needs a restart. There is no linter or formatter configured, and no frontend tests. The deepest test coverage sits where a bug would be silent: edition clustering, editor path containment, the fMP4 index parser, anonymous YouTube reads, and the pure AniList helpers. Tests point the app at a throwaway database through the client fixture — they never touch data/tubcal.db.
      
          
      Conventions
      
          
        
            
      • API endpoints return ok(data) / err(msg, status) — never a bare jsonify.
        • 
            
      • New external fetches go through server/httpc.py and are wrapped in server/cache.py with a TTL constant in server/config.py.
        • 
            
      • Anonymous reads use anonymous=True; every YouTube call site is either anonymous or authenticated.
        • 
            
      • Configuration is env-driven through config.py; runtime settings live in the DB and are read with db.get_setting(). All DB access goes through db.py — there is no ORM.
        • 
            
      • Heavy or native dependencies are imported lazily inside the function that needs them, never at module top level.
        • 
            
      • A room's view state belongs in the query string (useParamState in lib/urlState.js), not in useState.
        • 
            
      • Component CSS reads the design tokens through var(--token) — that's how every skin restyles it for free, down to the editor buffer.
        • 
          
      
          
      These docs
      
          
      This site is plain HTML, CSS and JavaScript in docs/ — no build step, no dependencies, fonts self-hosted. GitHub Pages serves it from the /docs folder of main. When the API changes, regenerate the reference with python docs/tools/extract_routes.py.
      
        
      
      
      

      
      
      
        
      
          13When a room goes quiet
      Troubleshooting
      
          
      Most “broken” rooms are a missing optional piece reporting itself unavailable, by design.
      
        
      
        
      
          
      A UI change doesn't show up.
      In production mode Flask serves the built frontend/dist. Run cd frontend && npm run build and hard-refresh. Backend changes need a server restart. In dev, run the Vite server on :5173 instead.
      
          
      The Anime channel says to connect AniList.
      AniList refuses unauthenticated queries, so the whole channel needs a connected account. Register an API client on AniList with the redirect URI shown in Settings → Connections (see Connecting accounts). AniList tokens last about a year and have no refresh flow — when one expires, reconnect.
      
          
      An episode won't play.
      The scrapers break when their sites change; the fix usually ships as an anipy-api release, which Tubcal installs on startup — restart the app. If you set TUBCAL_AUTO_UPDATE=0, update it yourself. If the first scraper can't resolve, the second one is tried automatically; you can prefer one with TUBCAL_ANIME_PROVIDER.
      
          
      The Dispatch has no scores and flat comments.
      That's Reddit logged out: it only serves RSS to anonymous clients. Create an OAuth web app at reddit.com/prefs/apps and connect it in Settings for full data.
      
          
      Videos only play at 360p.
      360p is the instant floor; higher renditions come from YouTube's DASH streams. A resolve that only produced the floor is cached briefly and heals on the next open. Make sure yt-dlp is on your PATH and reasonably current.
      
          
      The Archive or the written Edition says models are unavailable.
      Install the extra (uv sync --extra brain), start Ollama, and pull the models named in Settings (by default nomic-embed-text and qwen3.5:9b). Without them the Edition still prints a wire edition. If ML wheels fail to install, use Python 3.12 rather than a newer system Python.
      
          
      The Composing Room has no terminal or completion.
      The terminal and the LSP bridge need uv sync --extra editor; completion needs a language server on your PATH. Without them it's still a full editor. It can only reach TUBCAL_EDITOR_ROOT (default ~/Projects).
      
          
      The GitHub room stops loading.
      Unauthenticated GitHub allows 60 requests an hour per IP. Paste a classic personal access token into Settings, or set TUBCAL_GITHUB_TOKEN, for 5,000.
      
          
      Search says every Invidious instance failed.
      Search goes to YouTube's own InnerTube endpoint first; Invidious is only the fallback. If you need the fallback to work, point TUBCAL_INVIDIOUS at instances you trust.
